# Contributing

## Code of conduct

Review and follow the [Code of Conduct](https://github.com/dy0gu/.github/blob/main/CODE_OF_CONDUCT.md). It applies to everyone participating in this project.

## Questions and support

See the [Support Guide](https://github.com/dy0gu/.github/blob/main/SUPPORT.md) for general questions and implementation support. Reserve GitHub issues for bug reports and feature requests.

## Security

Review the [Security Policy](https://github.com/dy0gu/.github/blob/main/SECURITY.md). Do **not** report security vulnerabilities in a public issue.

## Issues

Before opening an issue, confirm that you are using the latest version of the project. Update first to see whether it resolves the problem.

## Pull requests

Before submitting a pull request for a non-trivial change, open an issue to discuss it. If an issue already exists, discuss the proposed approach there.

All contributions are licensed under the project's license.

## Code reviews

- Review the code, not the author. Suggest improvements without disparaging the author, and provide actionable feedback with supporting reasoning.
- Do not take constructive criticism personally. A review concerns the contribution, not the contributor.
- Note violations of these guidelines respectfully.

## Coding style

Follow the existing style, formatting, and naming conventions in the file you modify and throughout the project. Consistency lets reviews focus on functionality and performance rather than superficial changes.

Where possible, linters enforce style and formatting.
